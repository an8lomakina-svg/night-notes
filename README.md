# Night Notes

Статический персональный блокнот для GitHub Pages: задачи, планы, календарь, импорт `.ics`, голосовой ввод и озвучивание фокуса дня.

## Публикация на GitHub Pages

1. Создайте репозиторий, например `username.github.io`.
2. Загрузите в корень репозитория содержимое этой папки (не саму папку `night-notes`).
3. В GitHub: **Settings → Pages → Deploy from a branch → main / root**.
4. Откройте `https://username.github.io`.

## Синхронизация

Нажми «Моя ссылка» → «Скопировать ссылку» и открывай получившийся адрес в каждом браузере или на устройстве. Это один общий блокнот: данные загружаются при открытии страницы и обновляются при возврате к вкладке. Ссылка — ключ доступа, поэтому её нельзя пересылать посторонним. Вход по email остаётся альтернативным способом синхронизации. Локальная копия остаётся в браузере как запасной вариант.

## Google Calendar

Календарь поддерживает двустороннюю синхронизацию с основным Google Calendar:

- после подключения события из Google Calendar попадают в Night Notes;
- новые события Night Notes создаются в Google Calendar;
- изменение или удаление синхронизированного события применяется в обоих местах;
- при первом подключении все ранее созданные в Night Notes события отправляются в Google Calendar.

Для подключения один раз укажите OAuth Client ID типа **Web application** из Google Cloud. В его настройках добавьте JavaScript origin `https://an8lomakina-svg.github.io`, включите Google Calendar API и используйте scope `https://www.googleapis.com/auth/calendar.events`. Client ID сохраняется только в браузере; токен доступа не сохраняется, поэтому после перезагрузки страницы Google может попросить подключиться повторно.

Голосовой ввод использует Web Speech API и лучше всего поддерживается в Chrome/Edge. Нажмите маленькую оранжевую кнопку возле поля новой задачи и произнесите её.



## Сохранение и восстановление

Перед отправкой локальных изменений приложение читает облачную копию и объединяет независимые записи. Удаления отмечаются отдельно, чтобы синхронизация не возвращала удалённые записи. При конфликтующих изменениях одной записи отправка приостанавливается: в меню синхронизации можно скачать обе версии и выбрать нужные изменения. Успех показывается после проверки записанной облачной копии.

Приватная ссылка определяет открываемый блокнот и имеет приоритет над посторонней email-сессией. Привязка к приватному блокноту передаётся при установке приложения через cookie, ограниченную путём сайта. Проверка на реальном iPhone остаётся отдельной от автоматических тестов.

В меню синхронизации доступны скачивание текущей и предыдущей копий, а также загрузка JSON. Импорт добавляет записи к текущим; если версии одной записи отличаются, предлагается выбор. Нечитаемые локальные данные сохраняются отдельно, отображается восстановление, синхронизация приостанавливается.

## Проверки

Node.js 24 или новее:

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

`node test-sync.cjs` запускает актуальные интеграционные проверки синхронизации. Для установленного Chromium можно задать `BROWSER_EXECUTABLE`.

Тесты используют только искусственные записи и подменённые сетевые ответы. Проверяются формы, перезагрузка, фильтры, категории, покупки, заметки, календарь, вложения, архив, резервные копии, жесты, разные размеры экрана, ошибки хранилища и синхронизации, конфликтующие изменения с двух устройств. Они не обращаются к личным блокнотам и не проверяют реальные email/OAuth, радиопотоки или установку на iOS. В браузерных тестах внешние ресурсы заблокированы.

## Ярлык iPhone и браузер

У существующего ярлыка может быть отдельное хранилище. Если он пустой, в браузере с записями нажмите «Моя ссылка» → «Скопировать ссылку» и откройте полученный адрес. В прежнем пустом ярлыке можно нажать «Открыть мои записи» → «Вставить и открыть». Подключение читает и проверяет облачную копию, показывает записи без перезапуска и сохраняет привязку для следующих запусков. Оно не отправляет пустую копию в облако. Если в ярлыке уже есть записи или неотправленные изменения, подключение остановится для их защиты.

Для блокнота, привязанного к email, используйте один email в обоих экземплярах. После успешной миграции прежняя приватная привязка удаляется с этого устройства; облачная приватная копия не удаляется. Кнопка копирования ссылки для email-блокнота показывает инструкцию входа вместо создания расходящейся копии.

`tests/shortcut.cjs` проверяет подключение пустого ярлыка, повторный запуск, миграцию на email и отсутствие ложного статуса успеха для отсутствующей облачной копии. Проверка установки и входа на реальном iOS всё ещё необходима.

### Одна личная ссылка

Основной путь: «Моя ссылка» → «Скопировать ссылку». Открытие этой ссылки автоматически загружает тот же зашифрованный блокнот; отдельный мастер установки не запускается. Уже подключённый браузер запоминает привязку. Если ссылка потеряна, «Открыть мои записи» позволяет вставить её. Чтение буфера выполняется только по нажатию; при запрете доступна ручная вставка. Прежний вход по email и резервные копии сохранены в свёрнутых дополнительных настройках для совместимости с существующими данными.
